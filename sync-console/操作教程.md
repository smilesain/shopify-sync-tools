# 子站点素材同步台 · 操作教程

使用说明：如何安装、配置 Token、启动同步台，以及各模块的标准操作流程。

相关代码：

- 同步台：`sync-console/`
- 底层脚本：`custom-data-sync/`
- 简要说明：同目录 `[README.md](./README.md)`

---

## 1. 这是什么

本地可视化工具，把 **Source（源站）** 的部分 Shopify 后台数据同步到 **Target（目标站）**。

底层通过 Shopify **Admin GraphQL API** 读写；同步台只是封装了同级 `custom-data-sync` 下的脚本，并提供 Dry run / 实时日志。

请务必记住：

1. **每人在自己电脑上运行**（默认只监听 `127.0.0.1`，不能当团队共享线上服务）
2. **Token 只存在本机**，禁止提交到 Git、禁止发到聊天截图
3. **先 Dry run，再 Live**

---

## 2. 环境准备（每人一次）

### 2.1 软件要求

1. 安装 [Node.js](https://nodejs.org/)（建议 18+）
2. 拿到本仓库代码（clone 或拉取最新）
3. 确认存在目录：`sync-console/`、`custom-data-sync/`



### 2.2 申请 Admin API Token

在每个要参与同步的店铺后台创建 **Custom App**，安装后复制 **Admin API access token**（通常以 `shpat_` 开头）。

按实际要同步的内容勾选 scopes：


| 同步内容                        | 建议 scopes                                                                                                                  |
| --------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| Page / Blog / Article       | `read_content`, `write_content`                                                                                            |
| Product / Collection        | `read_products`, `write_products`                                                                                          |
| Collection 发布到 Online Store | 另加 `read_publications`, `write_publications`                                                                               |
| Menu                        | `read_online_store_navigation`, `write_online_store_navigation`                                                            |
| Template 图片 / 视频 Files      | `read_files`, `write_files`                                                                                                |
| Metaobject / Metafield 定义   | `read_metaobject_definitions`, `write_metaobject_definitions`, `read_metafield_definitions`, `write_metafield_definitions` |


建议：

- 源站至少具备对应的 **read_*** 权限
- 目标站具备对应的 **write_*** 权限
- 目标站也尽量开启对应 **read_***，以便按 handle 查找并更新已有资源

更完整的字段示例见：`custom-data-sync/.env.example`。

## 3. 启动同步台

在仓库**根目录**执行：

```bash
node sync-console/server.mjs
```

终端出现类似输出后：

```text
Shopify Sync Console
Open http://127.0.0.1:8787
```

用浏览器打开：**[http://127.0.0.1:8787](http://127.0.0.1:8787)**

### 可选环境变量


| 变量                  | 默认值         | 说明   |
| ------------------- | ----------- | ---- |
| `SYNC_CONSOLE_PORT` | `8787`      | 监听端口 |
| `SYNC_CONSOLE_HOST` | `127.0.0.1` | 监听地址 |


PowerShell 换端口示例：

```powershell
$env:SYNC_CONSOLE_PORT=8788; node sync-console/server.mjs
```

然后访问 `http://127.0.0.1:8788`。

### 启动失败常见原因


| 现象                           | 处理             |
| ---------------------------- | -------------- |
| 浏览器 `ERR_CONNECTION_REFUSED` | 服务未启动，先执行启动命令  |
| `EADDRINUSE` / 端口占用          | 关掉旧的同步台进程，或换端口 |

## 4. 配置店铺（第一次必做）

打开同步台后，在左侧 **「店铺」** 中配置 Source / Target。日常同步不必展开店铺管理。

### 方式 A：界面手动添加（推荐）

1. 展开「管理店铺列表」
2. 填写：
  - 显示名称（如 `smilesain`）
  - 店铺域名（如 `smilesain.myshopify.com`）
  - Access Token
3. 保存；再添加目标店铺
4. 在上方下拉框选择 **Source** 与 **Target**

> 方向选反会把数据写到错误店铺。操作前务必核对。



### 方式 B：从 `.env` 导入

1. 复制 `custom-data-sync/.env.example` 为 `.env`
2. 填入：

```env
SOURCE_STORE=source.myshopify.com
SOURCE_ACCESS_TOKEN=shpat_xxx

TARGET_STORE=target.myshopify.com
TARGET_ACCESS_TOKEN=shpat_xxx

SHOPIFY_API_VERSION=2025-01
```

1. 在同步台点击 **「从 .env 导入」**



### 凭证存放位置（本机）

- `sync-console/data/stores.json`
- `sync-console/data/selection.json`

以上文件已 gitignore，**不要提交**。

任务运行时，同步台会按所选店铺注入 `SOURCE_ACCESS_TOKEN` / `TARGET_ACCESS_TOKEN` 给底层脚本。

## 5. 日常同步标准流程

请按下面 6 步操作：

1. 确认 Source / Target 没有选反（可用「交换源/目标」）
2. 勾选需要的同步模块（建议先单项，不要一次全勾）；对应参数会显示在勾选项下方
3. 填写对应的 handle / Product ID / 模板文件
4. 左下角 **勾选 Dry run** → 点「开始同步」→ 阅读右侧日志
5. Dry run 无异常后，**取消 Dry run** → 再执行一次 Live
6. 到目标店后台核对结果

其他注意：

- 同一时间只允许一个任务
- 可随时点「取消」中断
- Dry run **不会**写入目标站；Live 才会写入

## 6. 各模块说明



### 6.1 Metaobject / Metafield 定义

同步的是**定义（schema）**，用于新店初始化结构；不是把所有业务实例数据一键搬完。

两种模式（两个模块各自独立）：

1. **留空**：同步源站全部定义（原行为）
2. **指定**：填写标识，只同步这些项（换行 / 逗号均可）
  - Metaobject：填 **type**（唯一标识），如 `compliance_profile`
  - Metafield：填 **namespace.key**；单独的 key 不唯一。可加 ownerType，如 `PRODUCT:custom.color`

源站找不到指定项会记为失败并继续其余项。

CLI：

```bash
cd custom-data-sync
node sync.mjs --only metaobjects --types compliance_profile,compliance_manufacturer --dry-run
node sync.mjs --only metafields --keys custom.color,PRODUCT:custom.spec --dry-run
```

### 6.2 Menu

两种模式：

1. **单个**：填写 Menu handle（如 `main-menu`）
2. **全部**：勾选「一次性同步源站全部菜单」
  - 分页拉取源站全部菜单并按序同步
  - 单条失败会继续后续菜单，最后汇总成功/失败数

需要导航相关 scopes。

CLI：

```bash
cd custom-data-sync
node sync-menu.mjs main-menu --dry-run
node sync-menu.mjs --all --dry-run
```

### 6.3 Page

两种模式：

1. **单个**：填写 handle（默认 `about-us`，可改成如 `store-locator`）
2. **全部**：勾选「一次性同步源站全部页面」
  - 分页拉取源站全部页面并按序同步
  - 单条失败会继续后续页面，最后汇总成功/失败数

CLI：

```bash
cd custom-data-sync
node sync-page.mjs about-us --dry-run
node sync-page.mjs about-us
node sync-page.mjs --all --dry-run
node sync-page.mjs --all
```



### 6.4 Blog 文章（Article）

两种模式：

1. **单篇**：填写 article handle（如 `test`）
2. **全部**：勾选「一次性同步源站全部 Blog 文章」
  - 分页拉取源站全部文章并按序同步
  - 目标站缺少同 handle 的 Blog 时会先创建
  - 单篇失败会继续后续文章，最后汇总成功/失败数

CLI 等价命令：

```bash
cd custom-data-sync
node sync-article.mjs test --dry-run
node sync-article.mjs test
node sync-article.mjs --all --dry-run
node sync-article.mjs --all
```



### 6.5 Collection

两种模式：

1. **单个**：填写 handle（默认 `robot-vacuums`）
2. **全部**：勾选「一次性同步源站全部集合」
  - 分页拉取源站全部集合并按序同步
  - 单条失败会继续后续集合，最后汇总成功/失败数

- 智能集合：同步规则（ruleSet）
- 手动集合：只把目标站**已存在的同 handle 产品**加入集合
- 缺少 publication 权限时会跳过「发布到 Online Store」，但集合本身仍可创建/更新
- 全量同步前建议先同步产品，否则手动集合成员可能对不上

CLI：

```bash
cd custom-data-sync
node sync-collection.mjs robot-vacuums --dry-run
node sync-collection.mjs robot-vacuums
node sync-collection.mjs --all --dry-run
node sync-collection.mjs --all
```



### 6.6 Product

两种模式：

1. **指定 ID**：一次填写多个数字 ID（换行 / 逗号 / 空格分隔），按顺序逐个同步
2. **全部**：勾选「一次性同步源站全部产品」
  - 分页拉取源站全部产品并按序同步
  - 单条失败会继续后续产品，最后汇总成功/失败数
  - 商品多时会跑很久，建议先 Dry run

示例：

```text
7549570941137
7549570941138
```

或：`111,222,333`

**会同步（概要）：**

- 标题、描述、handle、vendor、product type、tags、status
- 模板后缀、类目、SEO
- Options / Variants（SKU、条码、价格、对比价等）
- 图片（有数量上限）
- 部分 `custom` metafield（及可映射的 metaobject 引用）

**通常不同步：**

- 库存数量、仓库位置
- 销售渠道 / Publications
- 视频 / 3D 等非图片媒体
- 第三方 app 命名空间 metafield
- 集合归属、翻译 Markets 等



### 6.7 Template 图片 / 视频 Files

1. 勾选模块「Template 图片」和/或「Template 视频」，参数区会出现在下方
2. 在「Templates 目录」填写本机主题的 `templates` 绝对路径（例如 `E:\MyTheme\templates`）
3. 点击「扫描目录」列出 JSON
4. 勾选要同步的文件；也可在「额外 JSON 文件路径」粘贴绝对路径后执行

工具**不必**放在 Shopify 主题包内。目录选择会保存在本机 `data/selection.json`。  
也可用环境变量 `TEMPLATES_DIR` 作为默认目录。

CLI 示例：

```bash
cd custom-data-sync
node sync-template-files.mjs --dir="E:\MyTheme\templates" product.foo.json --dry-run
node sync-template-files.mjs "E:\MyTheme\templates\product.foo.json" --dry-run
```

## 7. 推荐同步顺序

多模块一起做时，建议按依赖顺序：

1. Metaobject / Metafield 定义（如需要）
2. Product（手动 Collection 依赖产品 handle）
3. Collection / Page / Blog Article / Menu
4. Template Files（图片 / 视频）

## 9. 常见问题排查


| 现象                        | 可能原因                       | 处理                                      |
| ------------------------- | -------------------------- | --------------------------------------- |
| `ERR_CONNECTION_REFUSED`  | 同步台未启动                     | 执行 `node sync-console/server.mjs` |
| `401 Invalid API key`     | Token 错误、过期或装错店            | 重新安装 App / 更新 Token，并确认店铺域名匹配           |
| `Access denied` / 缺 scope | Custom App 权限不足            | 补齐 scopes 后重新授权                         |
| Dry run 正常、Live 失败        | GraphQL userErrors、权限或字段冲突 | 看右侧日志具体报错                               |
| Collection 成员为 0          | 目标站没有同 handle 产品           | 先同步 Product，再同步 Collection              |
| 写到错误店铺                    | Source / Target 选反         | 立即停止，交换方向后重新 Dry run                    |


日志区域可实时查看每一步输出。任务无论成功、失败还是取消，同步台都会在 `custom-data-sync/reports/` 静默写入一份 `job-*.json`（含模块、步骤结果、日志尾部和错误摘录）。界面不展示报告列表，需要排查时直接打开该目录下的文件即可。

## 10. 安全与协作规范

1. Token 只放本机 `data/` 或本地 `.env`，不进 Git、不进群聊
2. 默认先 Dry run；Live 前再次确认目标店
3. 先小范围验证（1 个 handle / 1 个产品），再批量
4. 对已有同 handle 内容，Live 可能覆盖更新，操作生产店前要有确认
5. 同步台是本机工具，不要把 `127.0.0.1:8787` 当成团队共享服务地址转发给其他人「直接打开」——对方需要自己启动服务

## 11. 5 分钟快速上手清单

发给新同事时，可只转发本节：

1. 安装 Node.js，拉取仓库
2. 向管理员申请源站 / 目标站 Admin API Token（或自行创建 Custom App）
3. 根目录执行：`node sync-console/server.mjs`
4. 打开 [http://127.0.0.1:8787](http://127.0.0.1:8787)
5. 添加店铺 → 选择 Source / Target
6. 勾选一个模块 + **Dry run** → 看日志
7. 确认无误后取消 Dry run，再执行 Live
8. 到目标店后台核对

更细的模块说明见本文第 6–7 节。
